# Отчет по Лабораторной работе №9: Анимации, эффекты, тестирование и производительность

## 1. Что за приложение
«Задачник» (My Notes) — это современное мобильное приложение для управления личными, рабочими и учебными задачами, разработанное на базе **Jetpack Compose** и **Material 3**. Приложение использует архитектуру MVVM с локальной базой данных Room, поддерживает многопрофильность, облачную синхронизацию, адаптивную верстку для планшетов и телефонов, а также гибкое управление темами.

## 4. Модуль 3: Тестирование UI

### Написанные тесты (`AppUiTest.kt`):
1. **Тест рендеринга списка (`test1_listIsRendered`)**: проверяет появление главного экрана и наличие поля поиска (`TestTags.searchField`).
2. **Тест поиска с дебаунсом (`test2_searchFilteringWithDebounce`)**: симулирует ввод текста в строку поиска и проверяет работу фильтрации с учётом дебаунса.
3. **Тест добавления задачи (`test3_addNewTaskFlow`)**: проверяет сквозной сценарий создания новой задачи через экран редактирования (`TaskEditScreen`) и её появление в списке.
4. **Тест автосохранения / чекбокса (`test4_autoSaveCheckboxToggle`)**: проверяет интерактивность и реакцию списка на изменение статуса задачи.

### Почему используются semantics-утверждения:
Проверки на уровне семантики (`semantics`, `assertExists`, `onNodeWithTag`) взаимодействуют с деревом доступности (Accessibility Tree), а не занимаются попиксельным сравнением. Это делает тесты устойчивыми к изменениям размеров экранов, плотности пикселей и рендеринга шрифтов, обеспечивая высокую скорость и стабильность выполнения.

## 5. Модуль 4: Производительность

- **Отслеживание рекомпозиций (`Log.d`)**: в компоненте `ExpandableTaskCardView` добавлен вызов `Log.d("RECOMP", "TaskRow ${task.id}")`, что позволяет в Logcat отслеживать, какие именно карточки перерисовываются при изменениях.
- **Layout Inspector**: использовался для визуального анализа иерархии UI, проверки отсутствия избыточных вложенных контейнеров и контроля за количеством рекомпозиций.
- **`derivedStateOf` и `@Immutable`**:
  - Аннотация `@Immutable` на модели `Task` гарантирует Compose, что свойства объекта неизменяемы, позволяя пропускать рекомпозицию неизмененных элементов.
  - Использование `derivedStateOf` для фильтрации списка задач гарантирует, что список пересчитывается только при реальном изменении входных данных (список задач, поисковый запрос, приоритет), предотвращая лишние вычисления на каждый кадр скролла.

## 6. Модуль 5: Оптимизация

### Таблица замеров «До / После»

| Сценарий | До оптимизации | После оптимизации |
| :--- | :--- | :--- |
| **Клик по чекбоксу задачи** | Перерисовывался весь список (~200 элементов) | Перерисовывается только изменённая строка (`TaskRow`) |
| **Скролл длинного списка** | Заметные микрофризы (jank) | Плавные 60/120 FPS |
| **Поиск с фильтрацией** | Пересчёт фильтра на каждый символ без задержки | Дебаунс 300мс + кэширование через `derivedStateOf` |

### Важность `key = { it.id }` для `LazyColumn`:
Указание уникального ключа (`key = { it.id }`) в `itemsIndexed()` позволяет Compose однозначно идентифицировать каждый элемент списка. При изменении порядка, удалении или добавлении элементов Compose перемещает существующие ноды в иерархии UI вместо их полного пересоздания, что кардинально снижает нагрузку на сборщик мусора и ускоряет рендеринг.

## 8. Безопасность канала (Лабораторная работа №15)

В рамках лабораторной работы №15 по обеспечению безопасности сетевого взаимодействия реализованы следующие механизмы:

1. **HMAC-подпись запросов (`RequestSigner`)**:
   - Каждый исходящий сетевой запрос подписывается с использованием алгоритма **HMAC-SHA256** и секретного ключа (`"my_secret_key_123"`).
   - **Каноническая строка (Canonical-string)** формируется по строгому шаблону:
     `$method\n$path\n${body.sha256Hex()}\n$timestamp\n$nonce`
   - Передаваемые заголовки: `X-Timestamp`, `X-Nonce`, `X-Signature`.

2. **Защита от Replay-атак (`NonceCache`)**:
   - Реализован кэш уникальных одноразовых токенов (`nonce`) на базе `ConcurrentHashMap`.
   - Токены валидируются в окне актуальности **60 секунд**, повторное использование того же `nonce` или запросы вне временного окна отклоняются.

3. **WebSocket с экспоненциальным Reconnect (`LiveSocketManager`)**:
   - Подключение к `wss://echo.websocket.org` с поддержкой автоматического переподключения по алгоритму экспоненциальной задержки (1с, 2с, 4с, ..., макс. 30с).
   - Фреймы сообщений подписываются аналогично REST-запросам (`method = "WS"`, `path = "live"`).

4. **Network Security Config & Certificate Pinning**:
   - В `res/xml/network_security_config.xml` жестко запрещен незашифрованный трафик (`cleartextTrafficPermitted="false"`) для всех доменов в release-сборке.
   - Настроено закрепление сертификатов (Certificate Pinning) для `api.spaceflightnewsapi.net` с primary и backup SPKI-пинами.
   - Пользовательские CA (user-CA) по умолчанию не доверяются в release-конфигурации (fail-closed политика при ошибках рукопожатия TLS).
